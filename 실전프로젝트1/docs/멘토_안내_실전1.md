# 멘토 안내 (실전 1) — 안선민 멘토님

> 사용자가 전달받은 안내를 정리해 둔 것입니다. (2026-10-23 기록)

## 1. 제공 파일
- `pii_synth_finance_dev.jsonl` (100건): 개선·오류 분석용
- `pii_synth_finance_test.jsonl` (200건): 중간 확인용
- `run_compare.py`: 평가 지표 계산 코드

## 2. 라벨 변경
- 기업·기관명은 개인정보로 보기 어려워 **organization 라벨 제외**
- 라벨 7종, 개체 **1,713개** (dev 548 / test 1,165)

## 3. `run_compare.py` 사용법
- 결과는 문서당 한 줄 jsonl: `{"id": "D0002", "entities": [{"label": "person", "start": 53, "end": 57}], "ms": 12.3}`
- 위치는 원문 기준 파이썬 글자 위치, 끝 위치는 포함하지 않음 (`text[start:end]`). `ms`는 문서당 처리 시간
- 계산 지표: strict·partial 정밀도/재현율/F1, mask_rec, 라벨별 재현율, 어려운 사례 재현율, 일관성
- **오류 유형 분석, 합집합, 비교표 정리는 팀에서 직접**

## 4. 토큰 분류 기준 모델
- `BCCard/MoAI-Privacy-Filter-INT8` — https://huggingface.co/BCCard/MoAI-Privacy-Filter-INT8
- ONNX Runtime으로 실행 (transformers pipeline으로는 로드 안 됨)
- **모델 카드의 Viterbi 디코딩 코드를 그대로** 써야 공개 성능이 재현됨
- 모델 라벨 18종을 우리 7종에 직접 대응

## 5. 토큰 분류 추가 모델
- 기준 모델과 다른 한국어 개인정보 탐지 모델 **1개 이상** 비교
- 보고서에 라이선스, 크기, 학습 데이터, 라벨 대응 방식

## 6. LLM API
- 키는 매니저를 통해 제공. 환경변수로 관리, 저장소에 커밋 금지

## 7. 산출물 보고서
1. **데이터 관찰 리포트**: 라벨별 개수, 표기 형태(조사·띄어쓰기·이름만) 분포, 어려운 사례 태그 분포, 팀 라벨 기준('김 과장' 같은 표현 처리 등). 코드 없이 직접 분석
2. **방식별 비교표**: 정확도(**재현율·mask_rec 우선, 정밀도는 하한선**), 속도(CPU 기준 문서 1건 처리 시간과 1만 건 환산), 일관성(LLM 3회 반복). summary.csv와 화면 출력 활용
3. **오류 유형 분석**: 방식별 경계 오류·라벨 오류·미탐·오탐 **건수와 대표 사례, 원인 분석**. 예측과 정답을 직접 비교
4. **탐지기 선정 근거**: 비교 결과 + 운영 조건(**원문 외부 전송 가능 여부, CPU 환경, 라이선스**). **라벨별로 방식을 나눠 쓰는 조합도 가능**, 비교표 결과 인용

- **개선은 dev에서만, test는 중간 확인에만** 사용하고 그 과정을 보고서에 적을 것
