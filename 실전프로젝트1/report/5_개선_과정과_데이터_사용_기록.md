## 5-1. 원칙

- **개선은 dev로만** 하고, test는 중간 확인에만 쓴다(멘토 안내).
- holdout을 받지 못해, 일상 문서 1,983건을 반으로 나눠 **개선용(synth_dev 989건)**과 **오류를 끝까지 보지 않는 holdout(synth_holdout 994건)**으로 썼다.

## 5-2. 실제 사용 기록 (그대로 밝힘)

| 시점 | test 사용 | 비고 |
|---|---|---|
| v1 (첫 비교) | 점수와 **오류 목록을 봄** | 첫 비교 결과 확인 |
| v2 (모델 후처리, 규칙 일반화) | 점수 확인 | **v2 아이디어 일부(대표번호·민원번호 거르기, `신승현 과장` 유형)가 v1 test 오류를 보고 나왔다.** 구현은 dev로 했지만 같은 템플릿이라 test 정보가 간접적으로 들어갔다 → 제공 test 점수는 낙관적일 수 있음 |
| v3~v7 | **점수만 확인, 오류 목록은 보지 않음** | 멘토 안내 이후 원칙을 지킴 |
| 일상 문서 holdout | 처음부터 끝까지 점수만 확인 | 규칙 v5 → v6에서 오류를 보지 않았는데도 mask_rec 0.966 → 0.980 개선 = 일반화 근거 |

그래서 **처음 보는 문서 성능은 synth_holdout 점수(규칙 + 토큰 mask_rec 0.988)를 대표값으로** 본다.
