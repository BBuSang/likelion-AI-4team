## 요약

| 항목 | 결론 |
|---|---|
| **운영 탐지기** | **규칙 기반(정규식 + Kiwi) + 토큰 분류 모델(atonlee) 전체 합집합** |
| 선정 이유 | 모든 시험 데이터에서 놓친 개인정보가 가장 적음 — test mask_rec **1.000**, 처음 보는 일상 문서 mask_rec **0.988**. CPU만으로 문서당 약 0.1초(1만 건 약 19분), 결과가 항상 같고, 원문이 외부로 나가지 않음 |
| LLM의 역할 | **탐지에는 쓰지 않고 RAG 답변 생성에서만 사용** (마스킹된 텍스트만 전달). LLM을 더해도 재현율은 오르지 않고, 약 16배 이상 느리며, 원문을 외부로 보내야 함 |
| 우선 지표 | 재현율·mask_rec(놓치지 않기) → 정밀도는 하한선 0.90 → 속도 → 일관성 |
| 데이터 사용 | 개선은 dev(와 추가 데이터의 개선용 절반)로만, test는 중간 확인. 초기에 test 오류를 본 이력이 있어 그대로 밝힘(⑤ 개선 과정과 데이터 사용 기록) |

## 한계와 다음 단계

- **holdout 147건을 받지 못했다.** 받으면 지금 설정 그대로 한 번만 채점한다(`run_detect.py --split` 추가).
- **정밀도 개선 여지**: 합집합의 오탐 대부분은 토큰 모델의 구어체·상품명 오탐(`달래`, `하린`)이다. 문맥 없는 이름 후보에 신뢰도를 매겨 "규칙과 모델이 모두 동의할 때만" 채택하는 방식을 검토한다.
- **추가 데이터의 정답 품질**: 일상 문서 정답 검수(44건)를 팀 기준으로 마치면 수치가 더 정확해진다.
- **LLM 하이브리드는 처음 보는 문서에서 재지 않았다.** 다만 속도·외부 전송·일관성 문제는 데이터와 무관하다.
- 실전 2로 넘길 것: 같은 사람의 다른 표기(`윤 선영`/`윤선영`, `010.0349.2063`/`01003492063`) 정규화, 동명이인 구분, 메신저 호격 조사(`은영이`) 제거.

## 재현 방법과 파일 위치

```
cd 실전프로젝트1
python -X utf8 run_detect.py --detector rules --split test
python -X utf8 run_detect.py --detector atonlee --split test
python -X utf8 make_union.py --out preds/combined/rules+atonlee_test.jsonl preds/rules_test.jsonl preds/atonlee_test.jsonl
python -X utf8 run_compare.py --gold data/pii_synth_finance_test.jsonl --pred rules+atonlee=preds/combined/rules+atonlee_test.jsonl --out results/check
python -X utf8 experiments/compare_systems.py          # 규칙 / 토큰 / 규칙+토큰 비교표
python -X utf8 tools/make_compare_table.py test --rank  # LLM 7종 비교표 (팀원)
```
