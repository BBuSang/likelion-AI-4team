## 2-1. 비교한 방식

| 방식 | 구성 |
|---|---|
| **규칙 기반** | 정규식(전화·이메일·주민·계좌·카드·주소) + 형태소 분석기 Kiwi + 일반 성씨 목록 + 필드·호칭·직급·서명 문맥 규칙 + 문서 안 이름 퍼뜨리기 + 후처리(대표번호·장소 주소 제외). 데이터셋 인물 목록은 쓰지 않음 |
| **토큰 분류** | `atonlee/koelectra-ko-pii-ner` (KoELECTRA-small, 14M, Apache-2.0) + 같은 후처리. 팀원이 7개 모델을 비교한 뒤 속도·재현율로 선택(② 방식별 비교표 2-6) |
| **규칙 + 토큰** | 두 결과의 전체 합집합, 위치가 겹치면 규칙 쪽 경계 우선 |
| **LLM** | OpenAI gpt-4.1-mini, temperature 0, JSON 출력. LLM은 (값, 라벨)만 돌려주고 위치는 코드가 원문에서 찾음. 팀원이 7개 모델을 비교(② 방식별 비교표 2-5) |

## 2-2. 지표와 우선순위

| 순위 | 기준 | 지표 |
|---|---|---|
| 1 | 놓치지 않기 | **mask_rec**(정답 글자 중 가려진 비율), 재현율 — 놓친 개인정보는 벡터 DB·LLM으로 그대로 흘러감 |
| 2 | 정밀도 하한선 | strict 정밀도 **0.90 이상** — 너무 많이 가리면 검색·분석 품질이 떨어짐 |
| 3 | 속도 | CPU 기준 문서 1건 처리 시간, 1만 건 환산 (모델 로딩 제외) |
| 4 | 일관성 | 같은 문서를 3번 돌렸을 때 결과가 같은 문서 비율 |
