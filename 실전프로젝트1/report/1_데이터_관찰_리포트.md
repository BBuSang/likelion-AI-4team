# 실전 1 보고서 1부 ① 데이터 관찰 리포트

> - **과제**: 금융사 사내 문서에서 개인정보 7종을 찾는 탐지기를 규칙 기반·토큰 분류·LLM 세 방식으로 비교하고, 운영에 쓸 탐지기를 근거 있게 고른다.
> - **데이터**: 제공 `pii_synth_finance` dev 100건(정답 548개) · test 200건(정답 1,165개) / 추가 시험 데이터: 엣지 케이스 64건(정답 116개), 일상 문서 1,983건(정답 3,375개) / **멘토 holdout 187건(정답 912개)**
> - **채점**: 멘토 제공 `run_compare.py` (strict·partial 정밀도/재현율/F1, mask_rec, 라벨별·어려운 사례 재현율, 일관성)
> - **작성**: 2026-10-23, 수치 갱신 2026-10-26 (탐지기 v8) · 저장소 `hosung` 브랜치 `실전프로젝트1/` · 작업 기록 전체는 `worklog.md`

**보고서 구성**: 0 요약 및 결론 · **1부** ① 데이터 관찰 리포트 · ② 방식별 비교표 · ③ 오류 유형 분석 · ④ 탐지기 선정 근거 · **2부** ⑤ Holdout 데이터 관찰 · ⑥ Holdout 성능 · ⑦ Holdout 오류 분석 · ⑧ Holdout 개선 내역 · 부록 개선 과정과 데이터 사용 기록 (`report/` 폴더)

> **1부 수치 기준**: holdout 오류 분석 후 고친 **탐지기 v8**의 값이다. 이후 v9(부록 A-4)에서 dev·test·엣지 결과는 바뀌지 않았고, 일상 문서 평가용만 조금 올랐다(규칙 + 토큰 strict F1 0.956 → 0.961, mask_rec 0.988 → 0.989). holdout을 보기 전(v7) 값과 개선 전후 비교는 ⑥ Holdout 성능·⑧ Holdout 개선 내역 참고. 1부의 '일상 문서'는 팀이 만든 생성 문서(개선용 synth_dev / 평가용 synth_holdout)이고, 멘토가 준 holdout과 다르다.

## 1-5. 관찰에서 예상한 어려운 점과 추가 시험 데이터

| 관찰 | 예상한 어려움 | 대응 |
|---|---|---|
| 이름이 65%, 조사·띄어쓰기·이름만 표기 | 규칙이 이름 경계·이름만 쓴 경우를 놓침 | 형태소 분석(Kiwi), 호칭·필드·문서 안 이름 퍼뜨리기 규칙 |
| 템플릿 23종이 dev·test 공통 | dev 문구에 맞춘 규칙이 처음 보는 문서에서 무너짐 | 문맥 규칙을 끈 실험으로 하락 폭 추정(재현율 약 8%p) |
| 형식이 단조로움 (전화 010·02만, 계좌·주소 한 형식) | 실제 문서의 다양한 형식을 시험할 수 없음 | **엣지 케이스 64건**(지역번호·070·안심번호·+82, 은행별 계좌, 지번·읍면 주소, 외자·복성·외국인 이름 등)을 직접 작성 |
| 금융사 문서만 있음 | 일상 문서(상담·환불·배송·예약 등)에서의 성능을 모름 | **일상 문서 1,983건**을 OpenAI gpt-4.1로 생성 (카테고리 20 × 문체 5). 규칙 내용을 프롬프트에 넣지 않았고, **절반(994건)은 끝까지 오류를 보지 않는 holdout**으로 둠 |

추가 데이터의 한계: 엣지 케이스는 규칙 작성자가 써서 점수가 낙관적이고, 일상 문서 정답은 생성 모델이 표시해서 표시 누락 등 오류가 섞여 있다(검수 후보 44건, `results/synth_qc_candidates.csv`). 그래서 이 데이터들의 점수는 **절대값보다 방식 간 비교**로 쓴다.

## 1-6. 팀 라벨 기준

판단 원칙: **"이 값으로 특정한 사람을 알아낼 수 있는가"**

| 표현 | 판단 | 이유 |
|---|---|---|
| `김 과장`, `허 부장님` (성 + 직함) | **개인정보 아님** | 한 사람으로 특정되지 않음. 잡으면 실전 2에서 서로 다른 '김 과장'들이 한 토큰으로 합쳐짐 (데이터셋 정답 기준과 같음) |
| `소율 씨`, `승현아` (이름만) | 개인정보 | 문서 안에서 특정인을 가리킴 |
| 조사·호칭 (`윤선영은`, `김민수님`) | 범위에서 뺌 | 이름만 표시 |
| 회사 대표번호 `1599-0000`, `1588-…`, 080 | **개인정보 아님** | 콜센터로 연결될 뿐 상담사·고객 누구도 특정하지 않음 |
| 직원 직통번호 `02-3961-1452` | 개인정보 (그 직원) | 한 사람에게 연결됨 |
| 장소 주소 (웨딩홀·장례식장·회식 장소 등) | **개인정보 아님** | 누구나 찾아가는 장소. 단, 판단이 애매하면 가림(아래) |
| 집 주소, 배송지, 동·호수가 있는 주소 | 개인정보 | `직거래 … 902동 505호에서`처럼 장소 문맥이어도 동·호수가 있으면 집일 수 있음 |
| 휴대폰 번호를 계좌로 쓰는 경우 (토스 등) | 계좌 | `계좌`·`은행` 바로 뒤일 때. 어느 쪽이든 가려지므로 mask_rec에는 영향 없음 |
| 일부를 가린 값 `900512-2******` | 개인정보 | 보이는 부분만으로도 정보가 드러남 |
| 계좌 앞 은행 이름 | 범위 밖 | 번호만 표시 (데이터셋 기준) |
| 회사·기관·부서·상품명 | 개인정보 아님 | organization 라벨 제외 |

장소 주소는 **비대칭으로** 판단한다: 장소를 뜻하는 말(`장소:`, `식장`, `빈소`, `회식` …)이 확실히 있고, 개인을 가리키는 말(`주소`, `자택`, `배송` …)과 동·호수가 없을 때만 뺀다. 집 주소를 놓치는 것이 장소 주소를 가리는 것보다 훨씬 위험하기 때문이다.
