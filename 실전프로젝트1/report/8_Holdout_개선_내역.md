## 8-1. 무엇을 바꿨나 (탐지기 v7 → v8)

| 대상 | 변경 (파일) | 해결한 holdout 오류 |
|---|---|---|
| 1. 규칙 오탐 | 줄 맨 앞 `이름:` 규칙은 **문서 안에서 두 번 이상 말한 사람**이거나 서식 항목 접미사(`지·자·인·역·처·명·일·호`)로 끝나지 않을 때만 이름으로 봄. 명사 덩어리 규칙도 바로 뒤에 콜론이 오고 항목 접미사로 끝나면 제외 (`detectors/rule_based.py`) | `소명자:`, `위임인:`, `송금인:`, `배송지:` 오탐 34건 |
| 2. 규칙 오탐 | 직함 `심사역·조사역·검사역·감사역·상담역` 추가, 부고 단어(`장인상` 등)는 이름 아님 | `심사역` 3건, `장인상` 2건 |
| 3. 규칙 경계 | 사전에 없는 3글자 덩어리가 "이름 + 주격 조사 `이`"로 분석되면 조사를 뗌 | `안윤이`, `정별이` |
| 4. 규칙 미탐 | 필드 추가(`수취인·송금인·위임인·소명자·피해자·검토자·신고인·청구인·확인자·승인자·심사역`), 사람만 올 수 있는 필드는 일반 단어와 같은 이름도 받음, **띄어 쓴 외자**(`전 찬`) | `신설`, `전 찬` |
| 5. 규칙 형식 | 계좌 마지막 묶음 1자리(`056-75-340175-9`), 읍·면 바로 뒤 번지(`배방읍 252-4`), 주소 앞 우편번호(`(05299) …`) | 라벨 오류 3건, 경계 오류 5건 |
| 6. 토큰 후처리 | 부고 단어·회사 이름 끝말(`보안`, `시스템즈` …)로 끝나는 이름 제거, 단어 중간을 자른 이름 제거(앞이 호칭·직급이면 예외: `회원박희정님`), `○○ 번호`(사건·접수·주문 등) 뒤·`내선` 뒤 번호와 연도-일련번호 제거, 이름 뒤 `드림`·주격 `이` 제거, 주소 앞 우편번호 포함 (`postprocess.py`) | `미르보안`, `조모상`, `미수(신)`, 사건번호 5건, 내선 2건, `시우 드림`, `오가은이` |

모두 holdout 문장을 그대로 외우는 대신 **형식·문맥 규칙**으로 고쳤다(예: `소명자`라는 단어를 막지 않고 "콜론 앞 + 항목 접미사"를 막음). 한 글자 이름 `린`, 형용사 `정다운`은 고치면 일반 글자·단어를 이름으로 잡을 위험이 커서 남겼다.

**고치는 중에 생긴 회귀와 수정** (구성 요소별 비교로 발견)

| 회귀 | 원인 | 수정 |
|---|---|---|
| 메신저에서 한 번만 말한 사람 `신승현:`을 놓침 | 콜론 앞 단어를 모두 서식 항목으로 봄 | 항목 접미사로 끝날 때만 거름 |
| `고객: 김 과장`의 `김`을 잡음 | 1글자 첫 단어를 필드 값으로 허용 | 1글자는 띄어 쓴 외자일 때만 |
| 토큰 단독 test mask_rec 0.989 → 0.939 | 번호 문맥 정규식이 `주민등록번호`의 `등록번호`, `민원인`의 `민원`에 걸림 | `○○ 번호` 꼴만 보도록 수정 |

## 8-3. 처리 시간 (ms/문서)

- 이번에 추가한 후처리 자체는 **문서당 0.06ms**(holdout 187건 측정) → 속도 영향 없음.
- 같은 코드도 측정할 때마다 PC 부하로 토큰 모델이 문서당 45~100ms, 규칙이 1~7ms로 흔들렸다. 개선 전 48.1ms, 개선 후 연속 측정 54~102ms → **개선 전후 차이는 측정 오차 범위**로 판단했다(바뀐 코드는 정규식 후처리뿐).

## 8-4. dev·test·일상 문서 재확인 — holdout에 맞춘 수정이 기존 성능을 떨어뜨렸나?

| 데이터 | strict P (전 → 후) | strict F1 (전 → 후) | mask_rec (전 → 후) | ms/문서 (v8) |
|---|---|---|---|---|
| dev (100건) | 0.987 → 0.987 | 0.994 → 0.994 | 1.000 → 1.000 | 114.8 |
| test (200건) | 0.968 → **0.976** | 0.982 → **0.986** | 1.000 → 1.000 | 61.7 |
| 엣지 케이스 (64건) | 0.959 → **0.967** | 0.979 → **0.983** | 1.000 → 1.000 | 37.5 |
| 일상 문서 개선용 (989건) | 0.934 → **0.952** | 0.959 → **0.969** | 0.987 → 0.987 | 33.1 |
| 일상 문서 평가용 (994건) | 0.909 → **0.934** | 0.942 → **0.956** | 0.988 → 0.988 | 32.9 |

- **모든 데이터에서 떨어진 지표가 없다.** 정답과 정확히 일치하던 개체를 새로 놓친 경우 0건(전후 예측 비교로 확인).
- 특히 **오류를 한 번도 보지 않은 일상 문서 평가용에서도 정밀도가 0.909 → 0.934로 올랐다.** 서식 항목·회사·사건번호 오탐 제거가 holdout에만 맞춘 것이 아니라는 근거다.
- 다만 이것도 holdout 1개 세트로 고친 결과라, 진짜 일반화 성능은 **새 데이터(다음 holdout이나 실제 문서)로 다시 재야** 알 수 있다. 1부의 최종 선정(규칙 + 토큰)은 개선 전 holdout 점수(⑥)만으로도 유지된다.
