# Holdout 평가 보고서 — 개인정보 탐지기

> - **선정 탐지기 (개선 전)**: hosung 규칙기반(`rule_based.py`) + atonlee 토큰 모델 합집합 (팀 선정 모델)
> - **개선 후**: `hybrid_best` = 결합 규칙기반 `rules_best` + atonlee 합집합 + 모델 결과 거르기
> - **데이터**: dev 100건(정답 548개) · test 200건(1,165개) · **holdout 187건(912개)**
> - **채점**: `run_compare.py` (holdout 보강 태그를 지원하는 판). strict = 라벨·시작·끝 모두 일치, mask_rec = 정답 글자 중 가려진 비율
> - **작성**: 2026-10-26 · 코드·예측·채점 결과는 이 폴더(`hybrid/`)에 있음

## 요약

| | dev F1 | test F1 | **holdout F1** | holdout mask_rec |
|---|---|---|---|---|
| 선정 탐지기 (개선 전) | 0.994 | 0.982 | **0.944** | 0.993 |
| 개선 후 — dev 데이터로만 고친 부분 (`hybrid_best_nofix`) | 0.997 | 0.995 | 0.952 | 0.991 |
| 개선 후 — holdout 보강 포함 (`hybrid_best`) | 0.997 | 0.997 | **0.994** | 0.999 |

- **데이터가 바뀌면 성능이 떨어진다.** 선정 탐지기 F1은 dev·test 0.98~0.99에서 holdout 0.944로 내려갑니다. 재현율(0.978)과 mask_rec(0.993)은 유지됐고, 떨어진 쪽은 정밀도입니다(0.97~0.99 → 0.912).
- **오탐의 대부분은 처음 보는 문서 틀의 항목명입니다.** `위임인:`, `소명자:`, `송금인:`, `배송지:` 같은 단어가 이름으로 잡혔습니다.
- **holdout 오류를 보고 고친 뒤 F1은 0.994가 됐고, dev·test는 떨어지지 않았습니다.** dev는 0.997로 같고, test는 0.995 → 0.997로 올랐습니다.
- **다만 0.994는 holdout에 맞춘 점수입니다.** 처음 보는 데이터에서 기대할 성능은 `_nofix`(0.952)와 synth_holdout(0.950) 쪽이 더 정직한 추정입니다.

### 선정 탐지기의 강점
- **놓치는 개인정보가 적습니다**(mask_rec 0.993). 주민·카드·전화의 표기 변형은 규칙이 모두 잡았습니다(재현율 1.000).
- **두 방식의 약점이 겹치지 않습니다.** 규칙이 놓친 외자·이름만 쓴 경우는 모델이, 모델이 놓친 계좌 형식은 규칙이 잡습니다.
- **미끼에 강합니다.** 대표번호·번호 미끼 오탐은 0건이었습니다. 미끼 문서에서 생긴 오탐 8건은 모두 `정다운` 하나였습니다.

### 선정 탐지기의 한계
- **새 문서 틀의 항목명에 약합니다.** 이름 규칙이 "성씨로 시작하는 명사 덩어리"에 기대기 때문에, 처음 보는 항목명이 그대로 오탐이 됩니다(이름 오탐 58건 중 43건).
- **합집합이라 모델 오탐이 그대로 들어옵니다.** 회사명과 내선·사건번호가 그 예입니다.
- **외자 이름의 경계에 약합니다.** 외자 + 조사, 띄어 쓴 외자, 한 글자 이름이 해당합니다.

## ⑧ Holdout 개선 내역

### 개선 단계

holdout 오류를 보기 전에 dev 계열 데이터(dev, test, edge_cases, synth_dev)로 고친 부분과, holdout 오류를 보고 고친 부분을 나눴습니다. holdout을 보고 고친 부분은 환경변수 `PII_HOLDOUT_FIXES=0`으로 끌 수 있습니다.

> 데이터 사용 기록: 처음 두 규칙기반을 비교할 때 holdout 오류 목록을 한 번 봤습니다. 거기서 찾은 약점 3가지(우편번호, 읍·면 번지, 끝자리 1자리 계좌)는 처음부터 holdout 보강으로 분리했습니다.
> 2단계 수정 뒤 dev 계열 재확인 과정에서 synth_holdout의 오류도 일부 봤습니다(아래 3단계). 그래서 synth_holdout도 완전히 처음 보는 데이터는 아닙니다.

**1단계 — dev 계열 데이터로 고친 부분** (`hybrid_best_nofix`)
1. 규칙 결합: hosung 규칙을 기본으로 두고, 겹치지 않는 곳에 기존 kloid99 rules의 규칙을 더함
   - 날짜·성별 자리가 맞지 않는 6-7자리 주민번호
   - 메신저 이름 `은서랑`, `승현아,`
   - `XXX 님` 형태 이름
2. 이름 규칙 추가 (synth_dev 오류에서)
   - 콜론 없는 이름 칸 `예약자 설정윤`
   - 연락처 바로 앞 이름 `박민기(010…`
   - 서식 단어 제외 `배송지`, `송금자`, `진료일`, `홍콩행`
   - 끝 두 글자가 일반명사인 4글자 `우편번호`
3. 모델 이름 거르기: 규칙과 겹치지 않는 모델 이름이 아래에 해당하면 버림. 호칭·필드명 같은 이름 근거가 있으면 남김.
   - 일반명사 `이첩`
   - 문맥상 용언 `보고서 달래`
   - 상품명 `하린 포인트 카드`
   - 회사명 `미르보안`
   - 항목명 `고객명:`

**2단계 — holdout 오류를 보고 고친 부분** (`hybrid_best`)

| 수정 | 대상 오류 | 방법 |
|---|---|---|
| 우편번호 포함 | `(05299) 서울특별시 …` 경계 5 | 주소 바로 앞 `(5자리)`를 주소에 포함 |
| 읍·면 + 번지 주소 | `배방읍 252-4` 2 | `시·군·구 + 읍·면 + 번지` 패턴 추가. 장소 주소 판정은 원본과 같게 적용 |
| 끝자리 1자리 계좌 | `515-31-231761-6` 1 (+ 규칙 단독 미탐 5) | 마지막 묶음이 1자리인 2~4묶음, 숫자 10~14개 |
| 역할 명사 제외 | `위임인`·`소명자`·`송금인`·`심사역` 28 | Kiwi 분석상 **일반명사 2글자 + 자·인·역·관·주**이면 이름 아님. `김영자`·`박명인` 같은 이름은 해당 없음 |
| 이름 뒤 주격 조사 `이` | `안윤이 조건` 등 경계 5 | `한글 3~4글자 + 이 + 띄어쓰기`이고 뒤에 호칭이 없으면 `이`를 뗌. gold 정답 약 3,000개 중 `이`로 끝나는 한국 이름은 `정송이` 하나 |
| 서명어 잘라냄 | `시우 드림` 5 | 모델 이름 끝의 `드림·올림·배상` 제거 |
| 내선·사건번호 제외 | 번호 오탐 7 | 앞 문맥에 `내선`, `사건 번호`가 있는 모델 번호는 버림 |
| 단어 중간 조각 제외 | `미르【보안】` 1, `미르보안` 5 | 앞에 한글이 붙어 있는 일반명사 조각은 버림(띄어쓰기가 빠진 `회원박희정님`은 남김). 끝 두 글자가 일반명사인 4글자 이상은 직함 앞이라도 버림 |
| 거르기 보정 | `정설 카드번호`, `황 담 카드번호`, `상담사 재원:`, `심사역 오가은이` 미탐 | 1단계 거르기가 실제 이름을 지우고 있었음. `카드번호`는 상품명이 아님, `이름:`(화자)와 앞의 직함·역할 명사를 이름 근거로 인정 |

**3단계 — 2단계 회귀 수정**: 2단계 직후 dev 계열 재확인에서 생긴 오류를 고쳤습니다.
- 단어 중간 조각 규칙이 띄어쓰기 빠진 실제 이름(`회원박희정님`)을 지움 → 일반명사일 때만 버리도록 좁힘
- 새 이름 근거 때문에 `과장 장모상`, `외조모상`, `주 소:`가 살아남음 → 서식 단어·역할 명사·항목명 검사를 근거 확인보다 먼저 함

### 개선 전/후 점수 — holdout

| 단계 | strict P | R | F1 | mask_rec | 오류 수 |
|---|---|---|---|---|---|
| 개선 전: 선정 탐지기 | 0.912 | 0.978 | 0.944 | 0.993 | 85 |
| 1단계: dev 계열로만 고침 (`hybrid_best_nofix`) | 0.933 | 0.973 | 0.952 | 0.991 | 69 |
| 2단계 중간 (holdout 1차 3개만) | 0.945 | 0.981 | 0.963 | 0.997 | – |
| **최종: 2·3단계 포함 (`hybrid_best`)** | **0.991** | **0.997** | **0.994** | **0.999** | **11** |

라벨별 재현율 (정밀도), holdout:

| 라벨 | 개선 전 | 1단계 | 최종 |
|---|---|---|---|
| person | 0.995 (0.90) | 0.984 (0.93) | 0.995 (**0.99**) |
| phone_number | 1.000 (0.94) | 1.000 (0.94) | 1.000 (1.00) |
| address | 0.962 (1.00) | 0.962 (1.00) | **1.000** (1.00) |
| resident_registration_number | 1.000 (0.98) | 1.000 (0.98) | 1.000 (1.00) |

어려운 사례(holdout)는 최종본 기준으로 다음과 같습니다.
- account·address_format_variant: 0.957 / 0.951 → 1.000 / 1.000
- 나머지 항목: 개선 전과 같음

**1단계의 이름 재현율 하락(0.995 → 0.984)도 확인됐습니다.** dev 계열로 만든 모델 이름 거르기가 holdout의 실제 이름 일부(`정설`, `황 담`, `재원`, 외자 이름)를 지웠기 때문입니다. single_char_given_name이 0.947 → 0.895로 떨어졌고, 2단계 거르기 보정으로 다시 0.947이 됐습니다.

### 기존 성능 재확인 — holdout에 맞춘 수정이 dev/test를 떨어뜨렸는가

| 데이터 | 선정 (개선 전) | 1단계 | 최종 | 최종 − 1단계 |
|---|---|---|---|---|
| dev | 0.987 / 1.000 / 0.994 · 1.000 | 0.995 / 1.000 / 0.997 · 1.000 | 0.995 / 1.000 / 0.997 · 1.000 | 변화 없음 |
| test | 0.968 / 0.997 / 0.982 · 1.000 | 0.992 / 0.998 / 0.995 · 1.000 | 0.995 / 0.998 / 0.997 · 1.000 | 오탐 2 감소 (`미르보안`, `보안`) |
| edge_cases (64건) | 0.959 / 1.000 / 0.979 · 1.000 | 0.975 / 1.000 / 0.987 · 1.000 | 0.975 / 1.000 / 0.987 · 1.000 | 변화 없음 |
| synth_dev (989건) | 0.934 / 0.986 / 0.959 · 0.987 | 0.952 / 0.986 / 0.969 · 0.987 | 0.952 / 0.986 / 0.969 · 0.987 | 변화 없음 |
| synth_holdout (994건) | 0.909 / 0.979 / 0.943 · 0.988 | 0.923 / 0.978 / 0.950 · 0.988 | 0.924 / 0.978 / 0.950 · 0.988 | 오탐 3 감소, 1 증가 (`세대주:`) |

(각 칸: strict P / R / F1 · mask_rec)

**holdout에 맞춘 수정은 dev·test·추가 데이터의 성능을 떨어뜨리지 않았습니다.** 재현율·mask_rec는 모든 데이터에서 같고, 오탐만 일부 줄었습니다. 규칙 단독(`rules_best`)도 dev 1.000, test 0.998로 1단계와 같습니다.

### 처리 시간

같은 조건에서 holdout을 연속으로 쟀을 때, 2단계 수정 전후 모두 문서당 약 28ms였습니다(선정 탐지기 21.6ms). 같은 코드도 측정 시점의 컴퓨터 부하에 따라 28~66ms로 흔들렸습니다. `summary.csv`의 ms 값은 참고만 하세요.

### 남은 오류와 한계 (최종본, holdout 11건)

| 오류 | 건수 | 이유 |
|---|---|---|
| `정다운 금융 생활` 이름 오탐 | 8 | 형용사 활용형. Kiwi가 문맥에서도 고유명사로 분석해, 일반 규칙으로 구분하지 못함 |
| `전 찬` (띄어 쓴 외자), `린` (한 글자), `신설` (일반명사 이름) 미탐 | 3 | 규칙·모델 모두 이름으로 보지 않음 |

- **holdout 0.994는 holdout에 맞춘 점수입니다.** 처음 보는 문서에서 기대할 성능은 1단계 holdout(F1 0.952, mask_rec 0.991)이나 synth_holdout(F1 0.950, mask_rec 0.988)이 더 정확합니다. 최종본이 선정 탐지기보다 확실히 나은 점은 정밀도입니다. test 0.968 → 0.995, synth_holdout 0.909 → 0.924입니다.
- **역할 명사 규칙은 Kiwi 사전에 기댑니다.** 사전에 없는 항목명(`세대주`처럼 한 단어로 분석되는 경우)은 여전히 오탐이 될 수 있습니다.
- **새 시험 데이터가 필요합니다.** holdout과 synth_holdout은 이제 오류를 본 데이터입니다. 최종 성능을 확정하려면 규칙 작성자가 아닌 사람이 만든 새 데이터가 필요합니다.
