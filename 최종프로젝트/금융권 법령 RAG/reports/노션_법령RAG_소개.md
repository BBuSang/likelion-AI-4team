# ⚖️ 금융권 법령 RAG

금융 관련 법령 380개에서 질문에 맞는 조문을 찾아, 그 조문만 근거로 답하는 검색 증강 생성(RAG) 시스템입니다.

> 예: "자금세탁이 의심되는 거래는 어디에 언제까지 보고해야 해?"
> → 금융회사등은 의심되는 거래를 **금융정보분석원장에게** 보고해야 합니다(특정 금융거래정보의 보고 및 이용 등에 관한 법률 제4조). 보고대상 거래로 **결정한 날부터 3영업일 이내**에 보고해야 합니다(특정 금융거래정보 보고 및 감독규정 제3조).

---

## 1. 무엇을 만들었나

| 항목 | 내용 |
|---|---|
| 목표 | 금융권 직원이 일상어로 물어도, 근거가 되는 법 조문을 찾아 출처와 함께 답한다 |
| 답변 원칙 | 찾은 조문만 근거로 쓰고, 출처를 `법령명 제N조` 형태로 밝히며, 근거가 없으면 "관련 조문을 찾지 못했습니다"라고 답한다 |
| 속도 기준 | 질문 → 답변 완료 10초 이내 |
| 결과물 | 검색·답변 코드, 평가 체계(질문 1,000개), Streamlit 데모 |

---

## 2. 데이터

| 항목 | 수 |
|---|---|
| 법령 | **380개** (법률 171 + 시행령·시행규칙·감독규정 등 행정규칙) |
| 조문 | 28,510개 → 검색 대상 **26,603개** (삭제·본문 없는 조문 제외) |
| 검색 조각 (청크) | **35,321개** |
| 위임·준용 연결 | 11,477건 (위임 10,424 · 준용 1,053) |

- **출처**: 국가법령정보센터 Open API (현행 법령·행정규칙). 부칙·별표는 제외
- **전처리**: 법령은 API의 항·호·목 구조를 그대로 살려 줄 단위로 정리했습니다. 행정규칙은 줄바꿈 없이 한 덩어리로 오는 경우가 많아, 조문·항·호 경계를 규칙으로 다시 나눴습니다. 삭제 이력 태그(`<개정 …>`, `[본조신설]`)는 지우고, 계산식이나 별표 참조처럼 내용인 괄호는 남겼습니다.
- **청크**: 900자 이하 조문은 통째로, 넘으면 항 경계에서 600자 안팎으로 나눴습니다. 뒤쪽 조각에는 "이어서: ① …"처럼 상위 문장을 붙여 문맥을 잃지 않게 했습니다. 정의 조문(제2조 등)은 **정의 하나 = 조각 하나**로 나눴습니다.
- **점검**: 단계마다 판단 기준을 정해 통과 여부를 확인했습니다. 전처리 결과 140,638줄이 모두 원문의 일부임을 대조했습니다(새로 만든 글 0).

## 3. 전체 구조

```
질문
 ① 질문 임베딩 — KURE-v1 (로컬 CPU, 약 0.2초)
 ② 벡터 검색 — PostgreSQL + pgvector(HNSW)에서 조각 50개 → 조문 단위로 합침
 ③ 후보 만들기 — 1~10위 조문 + 1~5위와 위임·준용으로 연결된 하위·상위 법령 조문
 ④ 조문 글 — 여러 조각으로 나뉜 조문은 2,000자 이하면 전체를 넘김
 ⑤ 답변불가 판단 — 검색 1위 점수가 기준(0.5338)보다 낮으면 LLM 없이 "찾지 못했습니다"
 ⑥ LLM 한 번 — 후보 중 근거 조문을 골라 번호를 적고, 답변과 핵심 구절을 함께 씀
답변 + 근거 조문(출처 · 시행일자 · 본문 · 국가법령정보센터 링크)
```

| 구분 | 사용한 것 |
|---|---|
| 임베딩 모델 | `nlpai-lab/KURE-v1` (1024차원). 조각은 코랩 GPU, 질문은 로컬 CPU에서 같은 계산 |
| 벡터 DB | PostgreSQL 16 + pgvector (Docker), HNSW 색인 |
| 생성 모델 | OpenAI API, 질문당 1회 호출, 추론 강도 low |
| 데모 | Streamlit |
| 언어 | Python (transformers, psycopg, requests) |

키워드 검색(BM25)이나 별도의 재순위 모델은 쓰지 않았습니다. 대신 답변을 쓰는 LLM 호출 한 번 안에서 근거 조문을 고르게 해, 호출 수를 늘리지 않고 순위를 바로잡았습니다.

## 4. 성능을 올린 방법

| 바꾼 것 | 문제 | 효과 |
|---|---|---|
| **정의 조문 청크** | 용어 수십 개가 한 조각에 들어 있어, 용어 하나를 물으면 점수가 묽어짐 | 용어형 질문 1위 정답률 0.62 → 1.00 (처음 보는 세트) |
| **LLM 근거 선택** | 검색 1위가 법↔시행령, 이웃 조문끼리 근소한 차로 뒤바뀜 | 1위 근거 정답률 0.86 → 0.93 (호출 수 그대로) |
| **추론 강도 낮춤** | 추론이 길어지면 답변이 10초를 넘음 | 최대 13.7초 → 5.5초, 정확도는 같음 |
| **위임·준용 연결** | 답이 시행령에 있는데 검색은 법률만 찾음 | 검색 13위였던 시행령도 후보로 들어옴 |
| **조문 글 규칙** | 긴 조문의 한 조각만 넘겨, 답이 든 다른 항을 LLM이 못 봄 | 해당 오류 3문항 모두 해결 |
| **답변불가 기준점수** | 범위 밖 질문에도 LLM을 부름 | 답변 가능 500문항은 하나도 막지 않고 범위 밖 질문 절반을 LLM 없이 처리 |
| **답변 지시문 개선** | "2~4문장" 제한 때문에 목록·요건·예외를 빠뜨림 | 답변 정확 87 → 92 (처음 쓰는 세트) |

시험했지만 채택하지 않은 것도 기록했습니다. 예를 들어 "참고 조문은 근거에 넣지 마라" 지시는 처음 보는 질문에서 효과가 없고 일부 유형의 정확도가 내려가 채택하지 않았습니다.

## 5. 평가 방법

**평가셋**: 질문 1,000개 (dev1~10, test1~10 각 50문항)

- 질문은 실제 직원 말투로 쓰고, 정답은 질문을 만든 원본 조문입니다.
- 유형 5가지: 상황형(일상어), 용어형, 조문지정형("은행법 34조의2"), 하위법령형(금액·기간 → 시행령), 복수법령형
- 난이도 3단계: 쉬움 / 보통 / 어려움(긴 사례 + 헷갈리는 세부 조건)
- 범위 밖 질문 60개(날씨, 주식 추천, DB에 없는 법, 외국 법)를 따로 만들어 답변불가 처리를 평가했습니다.

**지표**

| 지표 | 뜻 |
|---|---|
| Hit@1 | 1위 근거 조문이 정답인 비율 |
| Hit@5 | 상위 5개 안에 정답이 있는 비율 |
| MRR | 정답 순위의 역수 평균 (1위 = 1, 2위 = 0.5 …) |
| 답변 정확도 | 정답 조문 전체 글을 기준으로 정확 / 부분 / 틀림 판정 |

**과적합을 막은 방법**

- 규칙은 법령·조문·질문 이름을 쓰지 않는 일반 구조 규칙만 씀
- 규칙을 만든 세트와 확인하는 세트를 나눔 — 만들 때 안 본 dev 세트로 다시 확인한 뒤 채택
- **test 세트는 세트마다 한 번만** 재고, 잰 세트는 코드로 잠가 다시 잴 수 없게 함. test 결과로는 아무것도 고치지 않음
- 채택 조건: ① 과적합 방지 ② 답변 10초 이내 ③ 품질은 전체·유형별·문항 단위로 내려가지 않음

## 7. 데모

Streamlit 한 페이지입니다.

- **입력**: 질문, 법령 구분 필터(선택), 왼쪽에 예시 질문 12개
- **답변**: 조문이 바뀌는 곳에서 문단을 나누고, 항목이 여러 개면 목록으로, 질문이 물은 **핵심 구절만 빨간색**으로 표시
- **근거 조문 카드**: 출처, 법령 구분, 시행일자, 검색 순위(연결 조문이면 표시), 국가법령정보센터 원문 링크, 본문 펼치기
- **디버그**: LLM에 넘긴 후보 목록, 단계별 시간, 토큰 수
- **점검 결과**: 예시 12개 모두 오류 없이 답변(최대 5.9초), 출처 형식·링크 정상, 범위 밖 질문은 0.15초 만에 "찾지 못했습니다"

## 9. 폴더 구조와 실행

```
최종프로젝트/금융권 법령 RAG/
├─ 기획안.md            기준 문서 (단계별 판단 기준, 변경 기록)
├─ WORKLOG.md           작업 기록
├─ pipeline/            수집 → 전처리 → 청크 → 임베딩 → 적재 → 평가 코드
├─ retriever/
│  ├─ search.py         검색 (임베딩, 벡터 검색, 연결 조문, 조문 글)
│  └─ answer.py         답변 (후보 → LLM 1회 → 답변·근거)
├─ demo/app.py          Streamlit 데모
├─ eval/                평가 질문·정답·결과
└─ reports/             단계별 점검 보고서, 최종 평가 보고서
```

```bash
docker compose up -d                                        # DB (PostgreSQL + pgvector)
python retriever/answer.py "예금자보호 한도는 1인당 얼마야?"   # 명령줄에서 한 번 묻기
python -m streamlit run demo/app.py --server.port 8504       # 데모 화면
```
