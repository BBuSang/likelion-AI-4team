# 사람이 쓴 평가 질문 세트 안내

지금까지의 평가 질문(합성, dev1~5, test1~5, final_test)은 모두 LLM이 정답 회신을 보고 썼고 정답이 하나뿐입니다. 그래서 점수가 실제 사용보다 높게 나올 수 있습니다. 이 세트는 **회신 원문을 보지 않은 사람이 쓰고, 정답을 여러 개 인정**합니다.

파일은 모두 `data/eval/human/`에 있습니다. 회신 원문 발췌가 들어가므로 저장소에 올리지 않습니다.

## 1. 질문 쓰기 (팀원, 1인당 10~15개, 합계 40~60개)

`questions.csv`를 엑셀로 열어 채웁니다. 빈 양식은 `python pipeline/h1_human_set.py template`로 만듭니다(이미 만들어 두었습니다).

| 칸 | 내용 |
|---|---|
| 작성자 | 이름 또는 별칭 |
| 업무 | 상품기획 / 준법감시 / 영업점 지원 / 여신 / 외환 중 가정한 역할 |
| 질문 | 은행 직원이 실제로 물을 법한 말투 그대로 |
| 추가 정답 | 3단계에서 포털에서 직접 찾은 사례번호 (예: `L123; O45`). 처음에는 비워 둡니다 |
| 메모 | 질문 의도, 헷갈린 점 |

지켜야 할 것
- **질문을 쓰기 전에 포털 회신이나 데모 화면을 검색하지 않습니다.** 답을 보고 쓰면 기존 세트와 같은 문제가 생깁니다.
- 본인 업무 경험이나 뉴스에서 떠오르는 궁금증을 씁니다. 답이 있을지 몰라도 됩니다. 답이 없는 질문도 "답변불가" 평가에 쓰입니다.
- 길이와 말투를 섞습니다: 한 줄 구어체, 검색어 나열, 상황을 길게 설명한 질문.
- 고객 이름, 계좌번호 같은 실제 개인정보는 쓰지 않습니다.
- 데모 개발자는 질문을 쓰지 않습니다(코퍼스와 시스템의 약점을 알고 있습니다).

## 2. 정답 후보 표 만들기 (개발자)

```bash
python pipeline/h1_human_set.py candidates
```

질문마다 검색 상위 20개 사례가 `labels.csv`에 들어갑니다. 다시 실행해도 이미 적은 판정은 지워지지 않습니다.

## 3. 판정하기 (질문을 쓴 사람이 아닌 다른 팀원 권장)

`labels.csv`의 `판정` 칸에 셋 중 하나를 적습니다.

| 판정 | 기준 |
|---|---|
| 정답 | 이 회신만 읽어도 질문에 답할 수 있다 (같은 쟁점, 같은 조건) |
| 관련 | 같은 주제지만 쟁점이나 조건이 달라 직접 답은 아니다 |
| 무관 | 질문과 상관없다 |

- 정답은 여러 개여도 됩니다. 하나도 없으면 모두 관련·무관으로 두면 되고, 그 질문은 답변불가 후보로 셉니다.
- 후보는 현재 시스템이 찾은 것뿐입니다. 시스템이 못 찾은 정답이 있을 수 있으니, 가능하면 포털에서 직접 검색해 보고 찾은 사례번호를 `questions.csv`의 `추가 정답`에 적습니다.
- 발췌만으로 판단이 어려우면 `원문` 링크를 엽니다.

## 4. 채점 (개발자)

```bash
python pipeline/h1_human_set.py score
```

```bash
python pipeline/h1_human_set.py score --final
```

- 질문은 번호(qid)로 개발용 절반과 시험용 절반으로 자동으로 나뉩니다.
- 첫 명령은 개발용 절반만 채점합니다. 기법을 고를 때는 이 점수만 봅니다. `--rerank`를 붙이면 리랭킹을 켠 점수를 봅니다.
- `--final`은 시험용 절반을 **한 번만** 채점하고 잠급니다. 설정을 모두 정한 뒤 마지막에 실행합니다.
- 지표: Hit@1, Hit@5, MRR@10. 정답으로 적힌 사례 중 하나라도(같은 묶음 포함) 맞으면 정답입니다.

## 5. LLM 심사 확인 (팀원 1~2명)

답변 품질 점수(정확도·충실도)는 LLM이 매겼습니다. 이 채점을 믿을 수 있는지 사람이 50개를 직접 판정해 비교합니다.

1. `judge_sheet.csv`를 엽니다(이미 만들어 두었습니다. 개발셋 답변 50개).
2. 질문, 시스템 답변, 정답 사례 내용, 답변이 인용한 사례 내용을 읽고 두 칸을 채웁니다.
   - 정확도: `일치`(정답 사례와 같은 결론) / `부분일치`(일부 쟁점만 맞거나 중요한 조건 누락) / `불일치`(반대이거나 다른 쟁점)
   - 충실도: `충실`(모든 주장이 인용한 사례에 있음) / `일부추정`(사례에 없거나 범위를 넘은 문장이 있음) / `근거없음`
3. `_judge_key.json`(LLM 판정)은 판정을 마칠 때까지 열지 않습니다.
4. 다 채우면 개발자가 비교합니다.

```bash
python pipeline/h2_judge_sample.py compare
```

결과로 사람과 LLM의 일치율, LLM이 후한지 박한지가 나옵니다.

## 6. final_test 정답 검수

final_test(100문항)는 정답 검수 없이 이미 한 번 평가했습니다. 검수해 다시 채점해도 독립적인 평가가 아니므로, 위의 사람 질문 세트 시험용 절반을 최종 수치로 쓰는 것을 권장합니다. final_test 점수는 "검수 전, LLM 생성 질문"이라는 조건을 붙여 참고로만 보고합니다.
