# Holdout2 리포트

Holdout2: 문서 756건, 검색 질의 155개, 탐지 정답 포함. 2026-11-26 받음. 모든 실행은 로컬 채점 DB(포트 5435)를 비우고 처음부터, 사람 손 없이 돌렸습니다.

## 1. 최종 성능 — 수정 없이 처음 돌린 결과

코드는 커밋 `001d685` 그대로, 입력은 `holdout2_public.jsonl`. 자세히: [1_first_run](1_first_run/README.md)

| 영역 | 지표 | 값 |
|---|---|---|
| 탐지 | strict P / R / F1 · 가리기 재현율 | 0.937 / 0.986 / **0.961** · 0.992 |
| 검색 | Hit@1 / Hit@5 / MRR | **0.910** / 0.961 / 0.931 |
| 답변 (gpt-6-luna) | 근거 적중 / 인용 적중 / 못 찾음 | 0.942 / 0.937 / 0.035 |
| 안전 | 원문 유출 LLM 입력 / 원 답변 / 최종 답변 | 8 / 0 / **0** |
| 시간 | 전체 | 1,307초 |

인용 적중과 유출은 채점 쪽 문제 때문에 다시 매긴 값입니다. 첫 실행 `report.md` 에는 각각 0.000, 0/0/0 으로 나옵니다. 이유는 [1_first_run](1_first_run/README.md) 의 '채점 주의'에 있습니다.

## 2. 막힌 곳과 고친 것 (실행 오류)

| 어디서 | 증상 | 원인 | 고침 |
|---|---|---|---|
| 화면 업로드 (적재 화면) | "345번째 줄: text 가 없음"으로 **파일 전체 거부** | 빈 문서 2건 (H20345 공백뿐, H20437 빈 글) | 빈 문서는 건너뛰고 나머지 754건 올림, 건너뛴 id 를 화면에 표시 (`service.parse_upload`) |
| 무인 파이프라인 | 멈추지 않음 (빈 문서도 적재) | - | - |
| 검색 재순위 | 오류 없이 **재순위가 효과 없음** | 문서 ID 를 4자리로 가정, `H20139` → `H2013` | ID 모양 가정 없앰 (`search._rerank`, `chat._CITE`) |
| 채점 | 인용 적중 0.000 | 같은 4자리 가정 | `run_pipeline._CITE` |
| 채점 | 유출 0/0/0 (검사가 빈 채로 통과) | `public` 입력엔 정답 값이 없음 | 이후 실행은 `labeled` 입력 (적재 땐 라벨 버림) |

ID 수정 후 다시 돌린 결과: 검색 Hit@1 0.910 → **0.935**, MRR 0.931 → 0.949 ([3_fix_id](3_fix_id/README.md))

## 3. 점수가 떨어진 원인

자세히: [2_analysis](2_analysis/README.md)

- **탐지 정밀도 0.937**: 이름 오탐 307건 중 300건이 양식에 반복되는 일반 단어 14개입니다(기안·양도인·소보·'안 돼요' 등). 주민번호 오탐은 법인등록번호, 계좌 오탐은 서버 IP 였습니다
- **미탐 → LLM 입력 유출 8**: 한글로 읽은 전화번호, 로마자 이름, 한 글자 이름이 원인입니다. 최종 답변에서는 0건이었습니다
- **동명이인 검색 (homonym_role Hit@1 0.375)**: 사람 잇기에서 고객과 직원 동명이인이 한 사람으로 합쳐졌습니다. '청구인'을 고객 항목으로 몰랐고, 표 안 이름에는 역할 단서가 없었습니다

## 4. Holdout2 를 보고 한 개선 (참고 점수 — 처음 보는 데이터 성능 아님)

자세히: [4_tuned](4_tuned/README.md)

| 지표 | 처음 | 개선 후 |
|---|---|---|
| 탐지 F1 / 가리기 재현율 | 0.961 / 0.992 | 0.998 / 1.000 |
| 검색 Hit@1 / MRR | 0.910 / 0.931 | 0.948 / 0.955 |
| 동명이인 질의 Hit@1 / 혼동 인용 | 0.375 / 0.238 | 0.750 / 0.000 |
| 답변 인용 적중 | 0.937 | 0.950 |
| 유출 LLM 입력 / 최종 | 8 / 0 | 2 / 0 |

이전 세트(holdout, synth_hard_eval, synth2, synth3, synth_fresh)는 개선 전과 점수가 같거나 1건 좋아졌습니다. 규칙이 Holdout2 양식에만 걸린다는 뜻이기도 합니다.
