# 17-1 목록형 답은 빠짐없이

## 왜
- '질문 두 개'(16-1)와 최종 검증(13-1)의 남은 실패 중에는 **근거에 있는 항목을 일부 빠뜨린** 답이 있었어요.
  - 거액기업자유예금 가입 대상: 법인 · 개인기업 · 개인사업자 중 '개인기업'을 빠뜨림
  - 국민연금 안심통장: 잔액증명 당일 출금뿐 아니라 입금도 안 된다는 점을 빠뜨림
- 답변 원칙 7번 "2~4문장으로 짧게"가 항목을 줄이게 만드는 것으로 보여요.
- 이 규칙은 질문이 하나뿐이어도 적용되므로, '질문 두 개'뿐 아니라 **모든 dev 세트**에서 확인해요.

## 바꾸는 것 (`LIST_RULE=1`, 답변 원칙 v9 뒤에 12번 추가)
> 12. 질문이 대상·조건·서류·방법·제한처럼 여러 항목으로 답해야 하는 것을 묻고 근거에 항목이 나열돼 있으면, 근거의 항목을 하나도 빼지 말고 모두 적는다.
>     7번(짧게)보다 이 규칙이 먼저다 — 항목은 쉼표로 이어 쓰고, 항목이 아닌 설명을 줄인다.
- 특정 실패 질문에 맞춘 조정이 아니라 일반 규칙이에요. 고르는 건 dev로만 해요.

## 판단 기준 (결과 보기 전에 기록)
| 항목 (dev, 지금 방식과 비교) | 기준 |
|---|---|
| 답변 정답 합계: 검색 dev 105 + 실제 말투 dev 34 + 공통 약관 dev 45 + '질문 두 개' dev 하위 질문 48 | **떨어지지 않음**, partial이 줄어야 함 |
| 세트별 답변 정답 | 어느 세트도 2문항 넘게 떨어지지 않음 |
| 없는 값 dev: 지어냄 | 늘지 않음 |
| 판매 상태·비교 dev | 판정 ok·correct가 떨어지지 않음 |
| 답변 길이 (검색 dev 105 글자 수 중앙값) | 30% 넘게 늘지 않음 |
- dev에서 통과하면 **새로 만든 잠금 세트**로 한 번 확인해요. 기존 잠금 세트는 이미 채점했으니 쓰지 않아요.
- 기준을 못 넘으면 넘었다고 말하지 않고 그대로 기록해요.

## dev 결과 (규칙 끔 → 켬)
| 세트 | 답변 정답 | partial |
|---|---|---|
| 검색 dev 105 | 98 → 99 | 6 → 4 |
| 실제 말투 dev 34 | 31 → 32 | 2 → 2 |
| 공통 약관 dev 45 | 39 → 39 | 2 → 4 |
| '질문 두 개' dev 하위 48 | 42 → 41 | 2 → 4 |
| **합계 232** | **210 → 211** | **12 → 14** |
| 없는 값 dev 32: 지어냄 | 0 → 0 | |
| 판매 상태·비교·빈틈 dev 70: ok·correct | 59 → 63 (비교 11 → 14, 판매 중 5 → 4) | |
| 답변 길이 중앙값 (검색 dev) | 107자 → 98자 | |
- **기준 미달이라 쓰지 않아요.** 정답 합계는 +1이지만, 기준으로 정한 'partial이 줄어야 함'을 넘지 못했어요(12 → 14).
- 판정이 바뀐 질문을 보면 좋아진 것과 나빠진 것이 비슷하게 섞여 있어요.
  - 검색 dev: 좋아짐 4 · 나빠짐 4
  - 공통 약관 dev: 좋아짐 3 · 나빠짐 1
  - 이 정도 차이는 LLM 답변이 매번 조금씩 달라지는 흔들림과 구분되지 않아요.
- 답이 길어지지도 않았어요. 모델이 원래도 근거의 항목을 대부분 다 적고 있었다는 뜻으로 보여요.
  - 동기가 된 실패 2개는 규칙이 없어서가 아니라 드물게 생기는 누락이었을 가능성이 커요.
- 비교 질문이 11 → 14로 오른 것은 이 규칙의 목표가 아니고 15문항뿐이라, 이것만 보고 쓰지 않아요.
- 동기가 된 실패 2개는 잠금·최종 세트에 있어서 dev 확인에 쓰지 않았어요(시험 세트를 보고 고치지 않음).
- 코드는 `LIST_RULE=0`(기본, 꺼짐)으로 그대로 둬요.
