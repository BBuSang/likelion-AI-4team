# 5-5 검색 평가셋 보완 — 같은 답을 담은 다른 문서도 정답으로 (2026-11-11)

## 왜
- 처음 평가셋은 정답이 **질문을 만든 섹션 하나**뿐 → 같은 상품의 특약·공통 약관·다른 섹션에 같은 답이 있어도 검색 지표에서 오답 처리
- 6-4에서 1위가 정답 섹션이 아닌 40개 중 32개는 그 1위만으로도 맞게 답함 → 검색 지표(Hit@1 62%)가 실제 쓸모보다 낮게 나옴

## 방법 (`analysis/s17_multigold.py`)
1. **후보 모으기 (pooling)**: 질문마다 vec·kw·routed 세 방식의 상위 10개를 합쳐(중복·원래 정답 제외, 최대 20개) 후보로. 재순위 같은 LLM 단계는 쓰지 않음 → 어느 방식에도 유리하지 않게
2. **판정**: CHAT_MODEL이 질문·정답·정답 근거와 후보를 보고 "**그 조각 하나만 읽고 정답과 같은 답(핵심 숫자·조건·대상)을 할 수 있는**" 후보만 고름. 일부만 있거나, 비슷한 이름의 다른 상품(다른 기간·회차)이면 제외. 확실하지 않으면 제외
3. **저장**: 질문에 `gold_alt` 추가 (청크 단위 `{doc_id, section_seqs}` · 공통 조항 · 용어). 원래 `gold`는 그대로. 판정 기록은 `data/eval/multigold_judgments.jsonl`
   - 청크 단위라 **청크 규칙을 바꾸면 다시 표시**해야 함
- dev·test 모두 표시 (test는 방식 고르기에 쓰지 않음, 마지막 한 번 채점용). 보완 전 파일은 세션 임시 폴더에 백업

### 사람 검수 (dev 무작위 14개)
- **13개 맞음** (특약 조항·공통 조항·다른 설명서 섹션·용어 부록에 같은 답이 실제로 있음)
- **1개 틀림**: 외화정기예금 "만기일이 공휴일이면 다음 영업일 자동해지" 질문에 다른 상품의 "휴일이면 직전 영업일부터 만기해지" 조항을 정답으로 표시 (내용이 반대) → LLM 표시의 정밀도는 약 13/14, 지표가 약간 후할 수 있음
- 덤으로 찾은 문제: 용어집의 `전세권`·`장래소득 인정기준` 정의 끝에 뒤따르는 "예금거래 지급동의서" 본문이 붙어 있음 (2-7에서 부록 마지막 용어의 범위를 넓게 잡음) → 다음에 2-7 용어 범위 수정

## 보완 후 검색 지표 (dev 105개)
| 방식 | 엄격 H@1 | **보완 H@1** | 엄격 H@5 | **보완 H@5** | 보완 MRR |
|---|---|---|---|---|---|
| vec | 0.467 | 0.629 | 0.781 | 0.924 | 0.746 |
| kw | 0.429 | 0.571 | 0.762 | 0.829 | 0.688 |
| hybrid | 0.457 | 0.705 | 0.848 | 0.933 | 0.799 |
| routed | 0.486 | 0.752 | 0.905 | 0.962 | 0.841 |
| rerank (목록형) | 0.600 | **0.914** | 0.952 | 0.971 | 0.936 |
| **rerank_score (점수형, 확정)** | 0.619 | **0.905** | 0.933 | **0.971** | 0.934 |
- 보완하면 **Hit@1 0.62 → 0.91** — 6-4의 "1위만으로 답했을 때 맞은 비율 96/105(91%)"와 거의 같음 → 보완 정답 표시가 답변 기준 결과와 서로 맞아떨어짐
- 방식 사이 순서는 그대로(재순위 > routed > hybrid > vec > kw), 재순위가 1위를 올리는 효과가 보완 기준에서 더 크게 보임 (routed 0.752 → 0.905)
- 목록형·점수형은 보완 기준으로도 차이 없음 → 점수형(흔들림 적음) 유지
- 앞으로 검색 지표는 **엄격·보완을 함께** 보고, 주 지표는 보완 Hit@1·Hit@5
