# 2-7 공통 조항·정형 문구·용어집 (2026-11-09)

- 스크립트: `analysis/s7_common.py` (LLM 없음). 실행 순서: `s5_split.py` → `s6_linebreaks.py` → `s7_common.py`
- 문제: 같은 문구가 여러 문서에 그대로 들어 있음 — 자료열람요구권 65개 문서, 위법계약해지권 58개, 휴면예금 51개, 예금자보호 45개 … 청크로 그대로 넣으면 검색 상위가 같은 문구로 채워져 상품 고유 내용이 밀려남
- 처리 원칙: **섹션은 하나도 지우지 않고 표시만** 함 (5,683개 그대로). 청크 단계에서 공통 조항은 한 번만 색인하고 문서와 연결(`document_clause`)

## 출력
| 위치 | 내용 |
|---|---|
| `data/sections/*.jsonl` 새 필드 | `clause_id`(공통 조항 번호, 없으면 null), `clause_docs`(그 문구가 나온 문서 수), `is_boilerplate`(정형 문구) |
| `data/meta/common_clause.csv` | 공통 조항 216개(보정 후): 제목, 문서 수, 정형 문구 여부, 원본 약관 문서(`terms_doc`), 대표 문구 |
| `data/meta/document_clause.csv` | 문서 ↔ 공통 조항 연결 (스키마 `document_clause`) |
| `data/meta/glossary.csv` | 용어집 23개: 용어, 정의(가장 많이 나온 것), 문서 수, 정의 변형 수, 출처 문서 |

## 규칙
1. **공통 조항** = 3개 이상 문서에 나오고 본문(제목 줄 제외) 40자 이상인 섹션 묶음
   - 같은 묶음: 정확히 같거나, 같은 제목 안에서 글자 4-gram 자카드 ≥ 0.9 + **숫자 목록 완전히 같음** + 다른 글자 4자 이하(문장 끝 `습니다.`↔`음`, 기호 `○` 정도)
   - 짧은 값(`재예치 / 불가`, `상품유형 / 자유적립식`)은 상품마다 답해야 하는 사실이라 묶지 않음
2. **정형 문구**(`is_boilerplate`) = 공통 조항 중 상품과 무관한 것
   - 제목이 권리(위법계약해지권·자료열람요구권·청약철회권·금리인하요구권 …)·민원/분쟁·휴면예금·압류 제한·거래중지·일반 유의사항·연체 불이익·'금리 등 아래의 내용은…' 안내·용어 부록
   - 약관 문서(`doc_type=약관`)의 조문이 다른 문서에 그대로 붙은 **사본** (투자설명서 7개 뒤의 예금거래기본약관 등 213개 섹션) — 원본 약관 문서 쪽은 정형 문구가 아님
   - 제외: 예금자보호여부·세제혜택·일부해지·이자율·만기 등 **상품 조건을 답하는 항목**은 공통 조항이어도 정형 문구 아님
3. **용어집**: 2-5에서 나눈 '용어 안내' 부록의 용어 섹션 (용어 뒤가 `•`·`▪`·`-` 설명일 때만 — 부록 뒤에 붙은 다른 표의 행 `대상`·`주택` 제외)

## 결과
- 공통 조항 218개 (정형 문구 67개), 공통 조항에 속한 섹션 1,436개(전체 글자의 27%), 정형 문구 표시 섹션 804개(17%)
- 많이 반복된 문구: `2. 거래조건 ☞ 금리 등 아래의 내용은…` 78개 문서, 자료열람요구권 65, 위법계약해지권 58, 휴면예금 및 출연 51, 예금자보호여부 45(상품 사실 — 정형 아님), 원금 또는 이자 지급관련제한 34, 거래중지 25, 세제혜택 23(상품 사실)
- 용어집 23개 (압류·근저당권·담보인정비율·총부채원리금상환비율 …), 13개는 문서마다 정의 표현이 조금 다름 → 가장 많이 나온 정의 사용

## 검증
1. 섹션 수 그대로(5,683), 글자 그대로 (필드만 추가)
2. **숫자가 다른데 같은 묶음에 든 공통 조항 0개** — 금리·기간이 다른 문구가 하나로 합쳐지지 않음
3. 처음에는 '근사 일치'를 자카드만으로 판단 → `자료열람요구권 … 양도및담보제공불가`처럼 **섹션 분할이 못 나눈 상품 사실이 끝에 붙은 문구**까지 같은 묶음에 들어가는 것을 표본에서 발견 → 다른 글자 4자 이하 조건 추가, 정형 문구 끝에 표의 행 이름(사전)이 붙어 있으면 정형 문구에서 제외
4. 표본 눈 확인: 정형 문구 15개(자료열람요구권, 거래중지, 붙은 약관 조문 …)·상품 사실 공통 조항 10개(중도해지 이자율, 세제혜택, 계약해지 방법 …) 분류가 맞음. 특약에 그대로 들어간 약관 조문(`제10조 예금자보호`)은 약관 사본으로 정형 문구 처리됨

## 보정 (3단계 전체 추출 중 발견, 2026-11-09)
- 전체 추출 표본 대조에서 D160의 `deposit_protected`가 비어 있음 → 원인: 섹션 분할이 못 나눈 `예금자보호여부 해당: …` 줄이 '휴면예금 및 출연' 섹션에 붙어 있었고, 그 섹션이 정형 문구로 표시돼 **LLM 입력에서 빠짐**
- 규칙 추가: 정형 문구 섹션 안에 **다른 표 행 이름(사전)으로 시작하는 줄**이 있으면 정형 문구가 아님 (`계약기간 등 변경에…`처럼 조사가 붙은 문장은 제외). 약관 사본 판정에도 같은 예외
- 결과: 26개 문서 31개 섹션이 정형 문구에서 빠짐 (예금자보호여부 14 · 계약해지방법 7 …) → 공통 조항 216개(정형 문구 62개), 정형 문구 표시 섹션 773개. 해당 문서는 추출을 다시 함

## 청크 단계에 넘길 것
- 정형 문구·공통 조항은 `common_clause`로 한 번만 색인 + `document_clause`로 문서 연결 → 상품 질문 검색에서 같은 문구가 상위를 채우지 않게
- 상품 사실 공통 조항(예금자보호여부 등)은 문서별 청크에도 남겨서, "○○ 적금 예금자보호 돼?"에 그 상품 출처로 답할 수 있게
- 용어 질문("근질권이 뭐야?")은 `glossary`로 답하고, 상품 질문 검색에서는 용어 부록을 낮춤
