# 답변 원칙 (신한은행 직원 보조 상품 RAG)

결정할 때마다 여기에 추가한다. 시스템 프롬프트·평가 질의셋을 만들 때 이 문서를 기준으로 한다.

## 1. 판매 중지 상품 (2026-11-09 결정, 같은 날 수정)
- 판매 중지된 상품을 물으면 **판매 중지된 상품이라는 사실을 먼저 답한다. 판매중지 날짜는 말하지 않는다.**
  > 신한 PAYCO 소액대출은 **판매 중지된 상품**이에요. 신규 가입은 안 돼요.
  - 수정 이유: 판매중지 날짜가 대출 목록에만 있고 예금·ELD(1,338건 중 1,247건)에는 없어 상품마다 답이 들쭉날쭉해짐 → 날짜는 데이터에서 제외
- 그 뒤에 가진 정보가 있으면 덧붙인다 (예: 기존 가입자용 고시 금리 + 기준일). 판매 중지 상품의 설명서는 지금 없으므로 세부 조건은 "문서 없음"으로 안내.
- 근거 데이터: `data/meta/discontinued.csv` (상품공시 판매 중지 목록 전체 1,338행) / `rate_product_map.csv`의 `sale_status`
- 판매 중 목록에도 같은 이름이 있는 상품(`also_on_sale=1`, 13개)은 판매 중지라고 단정하지 않고 "판매 중인 같은 이름의 상품이 있음"을 함께 안내한다.
- 판매 중·판매 중지 어디에도 없는 상품(`not_found`)은 "상품공시에서 확인되지 않는 상품"으로 안내하고 판매 여부를 단정하지 않는다.

## 2. 숫자에는 날짜를 붙인다
- 금리·금액이 들어간 답변에는 항상 기준일을 표시한다.
  - 고시 금리 → `as_of` (예: "2026-11-09 고시")
  - 설명서 금리 → 설명서 기준일 (예: "2026.10.16 현재, 세전")
- 기준일이 오래된 정보(예: 머니그램 수수료표 2018-06-19)는 "오래된 정보"라고 함께 알린다.

## 3. 숫자는 고시 금리, 조건은 설명서
- 금리 숫자는 **고시 금리(최신)** 를 우선, 우대조건·중도해지·유의사항은 **설명서(출처 문서·쪽)** 로 답한다.
- 둘이 다르면 날짜와 함께 둘 다 보여준다.

## 4. 대출 금리는 '예시 + 가정'
- 고시 대출 금리는 예시 금리이므로 **산출 가정**을 함께 말한다 (예: "1억5천만원·12개월·신용 3등급 가정").
- "실제 금리는 신용등급·담보 등에 따라 다름"을 붙인다.

## 5. 문서에 없는 수치는 지어내지 않는다
- 상품별 한도·금리·해약금률처럼 보유 문서에 없는 값은 "보유 문서에 없음 + 확인할 곳(여신 시스템·상품 안내·영업점)"으로 안내한다.
- 대출 공통 설명서의 **예시 숫자**(해약금률 1.4% 등)를 상품의 실제 값처럼 말하지 않는다.
- 규칙은 답하되 대출 유형별로 다른 규칙(기한의 이익 상실 시점 등)은 **상품 → 연결 설명서로 좁힌 뒤** 답한다.

## 6. 본문 우선
- 설명서의 **요약 상품설명서 쪽은 쓰지 않는다** (본문과 다른 경우가 있음: 예금자보호 5천만원 vs 본문 1억원).

## 7. 상품에 연결된 공통 문서는 유보하지 않는다 (2026-11-11)
- 근거가 공통 약관·약정서·대출 공통 설명서여도 **질문 상품에 연결된 문서**(`product_document`)이면 그 상품에 적용되는 문서다 → "이 상품에 적용되는지 확인되지 않는다"고 하지 않고 "○○ 기준"처럼 어느 문서 기준인지만 밝힌다
- 답변 모델에 근거마다 `[문서 층 · 질문 상품에 연결된 문서인지]`를 붙여 준다 (문서 층: 설명서 / 상품 특약 / 공통 약관 / 약정서 / 공통 조항 / 용어 안내)
- 다른 상품에만 연결된 문서는 근거로 쓰지 않는다

## 8. 문서끼리 다르면 상품 특약 우선 — 모순일 때만 (2026-11-11)
- 근거: 각 상품 특약 제1조 "이 특약에서 정하지 않은 사항은 예금거래기본약관 등을 적용한다", 예금거래기본약관 제23조(약관적용의 순서) — 개별 합의가 약관보다, 예금별 약관(입출금·거치식·적립식)이 기본약관보다 먼저
  - 주의: 제23조 자체에는 '특약'이라는 말이 없음 → 특약 우선은 특약 제1조와 제23조를 함께 근거로 든다
- 설명서의 요약 문장과 특약 규정이 **모순**되면 특약을 따른다 (예: 우대 나이 "만 18세 이하"(요약) vs "만 19세가 되는 달의 신규일까지"(특약))
- 모순이 아니라 특약이 "고시한 이율"처럼 값을 넘기고 설명서가 구체 값(이율·산식·기준일)을 적었으면 **설명서의 구체 값을 함께** 쓴다
- 특약 조항이 **다른 상황**을 다루면(예: '재예치 후 만기 전 해지' vs '연장 후 당초 만기일 이후 해지') 우선순위를 적용하지 않고 질문 상황에 맞는 조항으로 답한다 (6-2 검수에서 발견)
- 시행일처럼 문서마다 값이 따로 있으면 어느 문서의 값인지 밝히고 문서별로 함께 알린다

## 9. 답이 없을 때 안내 (2026-11-11, 8-1~8-3)
- 이미 근거로 본 문서를 다시 보라고 하지 않는다 (설명서에 없는데 "상품설명서에서 확인"이라고 하지 않음)
- 확인할 곳: 대출의 상품별 한도·기간·금리·수수료율 → **여신 시스템 또는 영업점 여신 담당** / 예금·기타 → **영업점 또는 신한은행 홈페이지 상품 안내**
- 상품명 찾기가 질문 속 상품을 못 찾았고 근거에도 그 상품 문서가 없으면: "보유 상품 목록에서 '○○' 상품을 찾지 못했습니다" → 정확한 상품명 확인 부탁 → 이름이 맞다면 위 확인할 곳 안내
  - **없는 상품이라고 단정하지 않는다** — 줄임말로 부른 실제 상품일 수 있음 (7-2: 줄임말 절반을 못 찾음). 다른 상품 값으로 대신 답하지 않는다
- 근거: 없는 값 dev 32개에서 지어냄 0, 가짜 상품 "목록에서 찾지 못함" 3/8 → 8/8 (`docs/8-3`)
- (9-1 추가) 상품명을 별칭으로 못 찾아 **줄임말로 추정**한 경우 답 첫머리에 "질문하신 '○○'을 '△△'으로 보고 답합니다"라고 밝힌다 — 잘못 짚었을 때 직원이 바로 알아채게

## 10. 판매 상태 (2026-11-12, 11-2 — 1번 원칙을 실제로 지키게 함)
- 질문 속 상품 이름을 판매 중 목록·판매 중지 목록과 대조해 답변 입력 맨 앞에 `[판매 상태]`를 준다
- 판매 중지: 첫머리에 "판매 중지된 상품이에요. 신규 가입은 안 돼요" → 날짜는 말하지 않음, 세부 조건은 지어내지 않고 기존 가입 고객은 영업점 안내. 다른 판매 중 상품으로 추정해 답하지 않음
- 양쪽 이름: 판매 중지라고 단정하지 않고 판매 중인 같은 이름의 상품 기준으로
- 판매 중: 판매 여부를 물으면 "판매 중인 상품이에요(상품공시 목록 기준)"
- 결과: 잠금 status_test 판매 중지 15/15 (이전 0/15) (`docs/11-1`)

## 11. 여러 상품 비교 (2026-11-12, 11-3)
- 질문에 상품이 둘 이상이면 모두 찾고, 근거를 상품마다 나눠 가져온다 (상품당 상위 3개, 최대 3개 상품). 근거마다 어느 상품 문서인지 표시
- 상품마다 **그 상품의 근거에서만** 값을 가져와 "상품 A: …, 상품 B: …"로 밝힌 뒤 비교 결론. 한쪽 값이 없으면 그 상품만 "확인되지 않음" — 다른 상품 값으로 대신하지 않음. 기준일이 다르면 함께
- 결과: 잠금 compare_test correct 0 → 7/8 (사람 기준 8/8) (`docs/11-1`)
- (11-5 추가) 판매 중지 상품을 줄임말로 불러도 상품명 찾기가 판매 중지 목록에서 후보를 골라 `[판매 상태] 판매 중지 (추정)`로 안내. 추정한 판매 중지 상품과 판매 중 상품이 함께 있으면 둘 다 알리고 어느 상품인지 확인 부탁 (답변 원칙 v8)
- (11-6 추가) 상품명을 추정으로 찾았으면(LLM 확인·고르기) 답변이 그 사실을 밝히지 않아도 코드가 맨 앞에 "(질문 속 상품 이름을 '△△'(으)로 보고 답합니다.)"를 붙인다 (답변 원칙 v9). 정식 이름 앞뒤에 낯선 말이 붙은 질문은 바로 확정하지 않고 LLM이 확인
