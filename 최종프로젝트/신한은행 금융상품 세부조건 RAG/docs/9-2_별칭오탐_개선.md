# 9-2 상품명 찾기 1단계 별칭 오탐 개선

## 왜
- 9-1 잠금 세트에서 남은 실수(줄임말 틀림 4 · 가짜 상품 1)가 모두 **1단계 별칭 정확 일치**에서 나옴 — 별칭이 맞으면 바로 확정해서 2단계(LLM 고르기)로 가지 않음
- 가짜 상품에 실제 상품을 붙이면 그 상품 값을 말하게 되는 길이 열림 → 지어냄 위험

## 원인 분석 (dev: alias_check 60 + alias_check2 110 + 검색 dev 105 — 9-1 잠금 세트는 채점이 끝나 이제 고치기용)
| 질문 속 호칭 | 맞은 별칭 | 1단계 결과 | 정답 |
|---|---|---|---|
| 가맹점대출 | 가맹점대출 (파생) | 땡겨요 우수 가맹점 대출 | 신한 가맹점 사업자 대출 |
| DB 정기예금 | 정기예금 (정식 이름) | 정기예금 | 퇴직연금 정기예금(DB) |
| 서울메이트 대출 | 서울메이트 (파생) | 서울 메이트 공무원·소방공무원대출 | 쏠편한 서울 메이트 공무원대출 |
| 상생대환대출 | 상생대환대출 (정식 이름) | 신한 상생 대환대출 | 신한 상생대환대출2 |
| 군인대출 | 군인대출 (파생) | 쏠편한 군인 대출 | 신한 군인행복대출 |
| 하모니 소상공인통장 (가짜) | 소상공인 (파생) | 소상공인 대출 2개 | 없음 |
- 공통점: ① 맞은 별칭이 상품 **정식 이름이 아니라 일부에서 만든 별칭**이거나, ② 그 별칭을 **이름 안에 품은 다른 상품**이 있음
- 이 두 신호 중 하나라도 있으면 바로 확정하지 않고 LLM 확인으로 넘기면: 오탐 6개 **전부** 넘어가고, 바로 확정되는 91개는 모두 맞음
- 비용: 정식 이름으로 묻는 dev 질문 92개 중 18개(약 20%)도 확인 단계로 넘어감 → 그만큼 약 2.8초 늘어남

## 구현 (`analysis/s12_retrieval.py`)
- `detect_products`: 별칭 정확 일치 → `alias_ambiguous`(① 파생 별칭 ② 그 별칭을 품은 다른 상품 있음)면 `detect_fallback(q, keep=1단계 상품)` — 1단계 상품을 후보 맨 앞에 넣고 이름 후보와 함께 LLM이 고름(맞으면 그대로, 아니면 다른 후보나 없음). 못 찾으면 9-1 2단계 그대로
- 비교용 `detect_v91` 유지, 끄기 `PRODUCT_VERIFY=0`. 고르기 지시문은 9-1 그대로 (줄임말별 규칙 없음)
- 답변: 최종 상품이 1단계 결과와 다르면 '(추정)'으로 표시 (9-1은 1단계가 못 찾았을 때만)
