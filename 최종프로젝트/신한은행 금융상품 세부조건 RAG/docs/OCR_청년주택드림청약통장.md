# OCR: 청년 주택드림 청약통장 상품설명서 (D238, 2026-11-09)

- 문제: 15쪽 모두 이미지라 PDF 텍스트 추출로는 1,332자뿐 (2-1에서 `ocr` 표시)
- 도구: **macOS Vision 문자 인식**(한국어 ko-KR 지원, 로컬 실행·외부 전송 없음) — `pyobjc-framework-Vision`, `pyobjc-framework-Quartz`를 공유 가상환경에 설치. Tesseract는 설치돼 있으나 한국어 데이터가 없어 쓰지 않음
- 스크립트: `analysis/ocr_pdf.py D238` → `data/text/청년 주택드림 청약통장 상품설명서.txt` (17,675자), 줄별 신뢰도 `data/ocr/D238_ocr.json`, 기존 추출본 백업 `data/text_ocr_backup/`
- 쪽을 300dpi 이미지로 바꿔 인식 → 위→아래, 같은 줄은 왼→오 순서로 정렬

## 품질 (원본 이미지와 직접 대조: p.2, p.8)
- **본문 문장은 거의 그대로** 인식 (숫자·날짜 포함: 5천만원, 7천만원, 2천만원, '25.1.1., 2021년 1월 1일 등)
- **복잡한 표는 셀 순서가 섞임** (예: p.8 '비과세 신청시 기타 서류 제출 기준' 표) — 텍스트 PDF의 표가 풀리는 문제와 같은 성격. 평균 신뢰도가 낮은 쪽(p.7 0.67, p.8 0.58)은 표가 많은 쪽
- 사소한 오류: 따옴표·괄호 일부 누락/변형 (예: '24.12.31 → 24.12.31)

## 발견: 다운로드 워터마크(개인 식별 정보 조각) 제거
- 쪽 맨 아래에 다운로드 기록 워터마크가 그림으로 찍혀 있음: `가려진 ID / 가려진 이름 / 다운로드 시각 + "고객정보 무단 반출 시 …" 안내문` 형태 (실제 값은 기록하지 않음) + 배경 대각선 'Shinhan One'
- 첫 OCR에 이 줄들이 섞여 들어옴 → **쪽 하단 4% 영역과 해당 문구를 제거**하도록 스크립트 수정 후 재실행, 텍스트·JSON 모두에서 0건 확인
- 나머지 246개 문서(텍스트 PDF)에는 이 워터마크 문구가 **없음**을 확인 (이미지로만 찍혀 있어 텍스트 추출에 안 잡힘)

## 후속 처리
- 2-1 ~ 2-4 재실행: D238은 `other` 형식, 인쇄 장식 30줄 제거, 15쪽 모두 본문, 심의필 `2026-13668-1`·유효기간 2026-07-29~2027-12-31
- 기준일 규칙 추가(`s4_meta.py`): 문서 맨 앞 300자 안의 `(2026. 07.23 기준)` → D238 기준일 2026-07-23 (다른 문서는 변화 없음). 설명서 기준일 99 → **100/118**
- `extract_pdf.py`를 다시 돌려도 OCR 결과를 덮어쓰지 않도록 보호 (텍스트 레이어가 거의 없는 PDF는 기존 결과 유지)
