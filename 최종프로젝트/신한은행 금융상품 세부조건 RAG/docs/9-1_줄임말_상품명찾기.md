# 9-1 줄임말 상품명 찾기 개선 (2026-11-11)

## 왜
- 상품명 찾기는 미리 만든 별칭(1,040개)과 **글자가 똑같아야** 찾음 → 줄임말 확인 질문(alias_check) 60개 중 **맞음 29 · 틀림 1 · 못 찾음 30**
- 못 찾으면 상품으로 좁히지 못해 다른 상품 문서가 섞이고, 8-3 이후에는 "보유 상품 목록에서 찾지 못했습니다"라고 안내하게 됨 (실제로 있는 상품인데도)
- 실패 유형: 글자 빼기·붙이기(한달적금, 새희망드림, 증권담보대출) / 영어↔한글(밸류업↔Value-up, 마이카↔MY CAR) / 일반어(적금, 당좌, 전세대출)

## 과적합을 막는 방법 (사용자 요청)
1. **줄임말마다 규칙을 손으로 넣지 않음** ('마이카=MY CAR' 같은 사전 없음) — 일반적인 방법 하나만
2. **잠근 확인 세트를 구현 전에 만듦** — `analysis/s22_alias_check2.py gen` → `data/eval/alias_check2.jsonl` 110개
   - 줄임말 60: alias_check·test2에 쓰지 않은 상품, s18과 **같은 지시문**
   - 가짜 상품 30: 실제 이름(판매 중·판매 중지)과 겹치지 않음 → 어떤 상품도 고르면 안 됨
   - 공통 질문 20: 상품 이름 없는 공통 규정·용어 질문 → 상품을 붙이면 안 됨
   - sha256 `212b7388703aa8472c2d6391a9e1ccf48fbe074b20a3488a759f54f534c5c7db` · 질문이 제대로 만들어졌는지만 읽음(판정 결과는 안 봄)
3. **고치기용(dev)은 따로**: alias_check 60(7-2에서 한 번 채점해 확인용 역할은 끝남 → 이제 고치기용으로 씀) + 8-1 가짜 상품 후보 중 absent test에 안 들어간 것 + 검색 dev의 공통 조항·용어 질문
4. **통과 기준을 결과 보기 전에 정함** (아래)

## 방법 (정해 둔 것)
- 1단계: 지금 별칭으로 정확히 찾으면 그대로 (정식 이름 질문은 지금도 잘 찾고 빠름)
- 2단계 (못 찾았을 때만): 질문과 상품 이름 313개를 **KURE 임베딩 + 글자쌍 겹침**으로 비교해 후보 최대 20개 → CHAT_MODEL이 "질문이 가리키는 상품"을 후보 중 0~3개 고름. 확실하지 않거나 해당 없으면 없음
  - 미리 확인: alias_check 60개 중 59개는 정답 상품이 후보 20개 안에 있음 (빠진 것: 'CD → 원화양도성예금증서')

## 구현 (`analysis/s12_retrieval.py`)
- `detect_exact` = 지금까지의 별칭 정확 일치, `detect_products` = 정확 일치 → 못 찾으면 `detect_fallback` (끄기: `PRODUCT_FALLBACK=0`)
- 후보: 이름 임베딩 상위 10 ∪ 글자쌍 상위 10 (상품 이름 313개, 이름 벡터는 embed_cache에) / 고르기 결과는 `data/chunks/product_pick_cache.jsonl`
- 답변(s15 v5 9번): 2단계로 찾은 상품이면 `[상품명 찾기] ○○ (추정)` → 답 첫머리에 "질문하신 '호칭'을 '상품 이름'으로 보고 답합니다" — 잘못 짚었을 때 직원이 바로 알아챌 수 있게
- `s20_absent_set.py`는 만들 때 쓴 `detect_exact`로 고정 (세트 재현용)

## dev에서 고친 것 (1번)
- 첫 판: 줄임말 맞음 29 → 56, 가짜 상품 17개 중 1개에 상품을 붙임 ('신한 작은틈 비상대출' → 쏠편한 비상금 대출)
- 고르기 지시에 **일반 원칙** 한 줄 추가: "상품을 구별하는 고유한 이름 부분이 맞아야 하고, 종류 말(대출·적금·비상금 등)만 겹치면 고르지 않음" → 가짜 0/17, 줄임말 맞음 55 · 틀림 2 · 못 찾음 3
