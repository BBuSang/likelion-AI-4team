## 최종 방식 (dev로 확정한 뒤 test는 이번에 처음 채점)
- 임베딩 **KURE-v1** (1024차원) → 질문에서 **상품명 찾기**(별칭 규칙, 같은 이름 상품 묶음 수정 포함) → 그 상품 문서·공통 조항·용어로 좁혀 **벡터+키워드 결합** → `gpt-6-luna` **점수형 재순위** 상위 5개 → **답변 원칙 v4**(근거마다 문서 층·상품 연결 표시, 연결 문서 유보 금지, 모순일 때만 상품 특약 우선, 다른 상황 조항은 앞세우지 않음)
- 실행: `s12_retrieval.py test routed rerank_score`, `s15_answer_eval.py test 5 --version=v4 --retrieval=rerank_score --final` → `data/eval/answer_eval_test.jsonl`
- test 72개 = 상품 단위로 dev와 나눈 질문 (상품 사실 60 · 공통 조항 8 · 용어 4), 추가 정답(gold_alt)은 5-5에서 방식과 무관하게 표시해 둔 것

### 실제 실패 원인 (A141)
- "마이홈플랜은 …"에서 `마이홈플랜`이 별칭에 없음: 별칭 규칙이 상품 이름의 **뒤쪽 어절**(종합저축 등)만 만들고 앞쪽 브랜드 어절(`마이홈플랜`)은 만들지 않음
- 대신 질문 속 일반어 `청약통장`이 "청년 주택드림 청약통장"의 뒤쪽 어절 별칭으로 걸려 **엉뚱한 상품(청년 주택드림)으로 좁힘** → 정답 문서가 후보에서 빠짐. 겹침 거름(4개 이상 상품이면 버림)을 통과한 일반어(2개 상품에만 걸림)
- 고칠 방향: 앞쪽 브랜드 어절도 별칭으로, `청약통장`·`적금`처럼 상품 종류를 뜻하는 일반어는 별칭에서 빼기, 상품명을 못 찾거나 애매하면 좁히지 않거나 되묻기
- **주의**: 이 문제는 test에서 찾았으므로 고치고 나면 test는 더 이상 깨끗한 시험 세트가 아님 → 고친 뒤 성능은 새 질문으로 확인해야 함
