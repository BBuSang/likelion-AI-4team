# 4-3 임베딩 모델 KURE-v1로 바꾸기 — 코랩 실행 (2026-11-11)

## KURE-v1 (모델 카드 확인)
- `nlpai-lab/KURE-v1`: BAAI/bge-m3를 한국어 질의-문서 약 200만 쌍으로 미세조정, **1024차원**, 최대 8,192 토큰, 0.6B, **MIT**
- sentence-transformers로 사용, 질문·문서 앞에 붙이는 지시문(prefix) 없음 → 질문과 문서를 같은 방식으로 encode, 코사인 유사도
- GPU가 있으면 빠르므로 **코랩 GPU**에서 임베딩하고 결과 파일만 로컬로 가져옴

## 흐름
```
[로컬] python analysis/s10_chunks.py export-colab
       → data/colab/embed_input.jsonl (청크 2,218 · 공통 조항 216 · 용어 23 = 글 2,457개 + 평가 질문 177개, 3.1MB)
[코랩] notebooks/kure_embed_colab.ipynb (런타임 GPU) — 파일 올리기 → KURE-v1 fp16 → 정규화 임베딩 → embed_output.jsonl 내려받기
[로컬] 결과를 data/colab/embed_output.jsonl로 두고
       1. .env: EMBED_MODEL=nlpai-lab/KURE-v1, EMBED_DIM=1024
       2. python analysis/s10_chunks.py import-colab data/colab/embed_output.jsonl   (해시·개수·차원 확인 후 캐시에 합침)
       3. python analysis/s9_load_db.py          (스키마 벡터 차원을 .env EMBED_DIM으로 다시 만듦)
       4. python analysis/s10_chunks.py load
       5. python analysis/s12_retrieval.py dev routed rerank   (OpenAI와 같은 평가셋으로 비교)
```

## 코드 변경
- 임베딩 캐시 `data/chunks/embed_cache.jsonl`을 **(모델, 내용 해시)**로 구분 → OpenAI·KURE 벡터가 한 파일에 있어도 섞이지 않음. `.env`만 바꾸면 두 모델을 오가며 비교 가능
- `s10_chunks.py`: `export-colab` / `import-colab` 추가, `embed`는 OpenAI 모델일 때만(아니면 코랩 안내), `load`는 그 모델 벡터가 다 있는지 먼저 확인
- `s12_retrieval.py`: `.env` 모델의 벡터만 읽음. OpenAI가 아닌 모델은 질문 벡터도 코랩 결과에서 가져옴(평가 질문은 입력에 포함)
- `s9_load_db.py`: 스키마의 `vector(1536)`을 `.env`의 `EMBED_DIM`으로 바꿔 만듦
- 확인: 가짜 1024차원 벡터로 시험 폴더에서 `import-colab` → 2,634개 모두 들어가고 OpenAI 캐시와 분리됨, `load`에 필요한 벡터 빠짐 없음. 노트북 코드 셀 문법 확인. **실제 KURE 임베딩은 코랩 실행 후**

## 주의
- **실제 서비스에서 새 질문을 임베딩하려면 KURE-v1을 어딘가에서 돌려야 함** (OpenAI처럼 API 호출이 아님). 질문 1개는 CPU·맥 MPS로도 가능하지만 응답 시간 확인 필요 — 답변 단계에서 정함
- 평가셋 질문을 바꾸면 export-colab부터 다시 (질문 벡터도 코랩에서 만들기 때문)
- `embed_input.jsonl`에는 상품 문서 본문이 들어 있음 → 코랩 사용 후 런타임 삭제

- 다음: 재순위의 흔들림을 재기 (같은 후보로 여러 번·후보 순서 섞기) → 그 뒤에 모델 결정. test는 결정 전까지 KURE로 채점하지 않음
- 이 비교 중 `.env`는 KURE, DB는 1024차원 KURE 벡터로 적재된 상태

## 재순위 흔들림 재기 (`analysis/s13_rerank_stability.py`, 2026-11-11)
- 방법: 두 모델 각각 dev 105개 질문의 routed 상위 10개 후보를 고정하고, **후보 순서만 섞어** CHAT_MODEL 재순위를 3번씩 (모델당 315번 호출, 결과 `data/eval/rerank_stability.jsonl`)

| dev 105개 | OpenAI | KURE |
|---|---|---|
| H@1 반복별 | 0.657 · 0.657 · 0.657 | 0.676 · 0.610 · 0.657 |
| **H@1 평균** | **0.657** | **0.648** |
| H@5 평균 | 0.937 | 0.937 |
| 3번 모두 1위가 같은 질문 | 76% | 71% |
| 한 번이라도 1위 정답 | 76% | 75% |
| 매번 1위 정답 | 56% | 53% |
| 후보 10개 안 정답 | 95% | 96% |
- **재순위 후 두 모델 차이(0.657 vs 0.648)는 흔들림보다 작음** → 앞서 본 0.705 vs 0.600은 재순위 한 번의 우연이 컸음. OpenAI 쪽 H@1이 3번 다 0.657인 것도 질문마다 1위가 바뀐 것이 합계로 같아진 것(1위 일치 76%)
- **재순위 자체가 많이 흔들림**: 후보 순서만 바꿔도 질문 4개 중 1개는 1위가 바뀜 → 답변 품질에 영향. 개선 후보: 후보마다 점수 매기기(목록 순서 대신), 순서를 바꿔 여러 번 묻고 투표, 상위 몇 개를 함께 답변에 넣기
- **결정: KURE-v1** — 재순위 후에는 차이가 없고(흔들림 안), 재순위 전 단계(벡터·결합·상품명 좁히기)는 모든 지표에서 앞서며 후보 10개 재현율도 같거나 높음. 재순위를 줄이거나 빼야 할 때(응답 시간) 더 유리. 대신 질문 임베딩을 직접 돌려야 함
