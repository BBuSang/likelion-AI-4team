# 3-0 LLM 추출 준비 (2026-11-09)

전처리(2-1~2-7)가 코드로 끝나면서, 처음 받아 온 추출 스키마의 일부는 LLM이 할 필요가 없어졌다. LLM은 **표의 숫자·조건을 정형 데이터로 옮기는 일**만 한다.

## 바뀐 점
| 항목 | 이전 (받아 온 스키마) | 지금 |
|---|---|---|
| 섹션 나누기·정형 문구 표시 | LLM이 `sections`로 출력 | 코드 (2-5·2-7) → 스키마에서 삭제 |
| 심의필 번호·유효기간·기준일 | LLM | 코드 (2-4 `doc_meta.csv`) → 스키마에서 삭제 |
| 입력 | PDF 텍스트 전체 | 정형 문구를 뺀 섹션 정리본, `[S번호] 섹션 경로 (p.쪽)` 머리 |
| 근거 | `source_text`만 | `section_seq` + `source_text` → 코드가 그 섹션에 정말 있는 문장인지, 숫자가 그 문장에 있는지 검사 |
| detail 종류 | 카드·펀드 포함, LLM이 category 판정 | 범위에 카드·펀드 없음 → `Deposit/Loan/InvestDetail`, 종류는 연결 상품 분류로 코드가 정해 입력에 줌 |
| 금리 종류 | 예금·대출 기본 | + ELD 모집기간이율·지수연동이율, 대출 감면금리, 연체이자율, 통화(외화예금), 세전/세후 |
| 수수료 종류 | 카드 연회비·펀드 보수 | 중도상환해약금, 중도해지수수료(ELD), 금·은 스프레드·실물 인출, 외화 현찰, 인지세, 한도 수수료 |
| 확정 못 한 값 | 규칙 없음 | 표가 섞여 짝이 불확실하면 추출하지 않고 `notes`에 기록 → `document.extract_notes` |

## 파일
- `models/models.py` — `DocumentExtraction` (요약 칸 + detail + rates/fees/benefits + notes)
- `models/extract_prompt.md` — 다시 작성: 빈칸 서식·예시 계산 숫자는 값이 아님, 구간·조건마다 한 항목, 원문 그대로 복사
- `models/schema.sql` — `doc_rate`에 `currency`·`section_seq`, `pre_tax` 기본값 제거(원문에 없으면 null), `doc_fee`·`doc_benefit`에 `section_seq`, `document.extract_notes`, 종류 값 주석 갱신. 임시 pgvector DB 적재 확인
- `analysis/s8_extract.py`
  - `check`: models.py ↔ 프롬프트 ↔ schema.sql 일치 검사(필드가 DB 열에 있는지, 종류 값이 주석·프롬프트에 있는지, 옛 스키마 흔적, OpenAI 구조화 출력(strict) 변환) → **통과**
  - `input D156`: 문서 1건의 LLM 입력 미리보기, `targets`: 대상 목록
  - `verify()`: 근거 검사 — 지어낸 문장·숫자를 넣은 시험 항목을 잡아내는 것 확인

## 추출 대상
- 상품 조건 표가 있는 **상품설명서 118 + 간이투자설명서 6 + 투자설명서 6 = 130개 문서**, 입력 합 약 73만 자 (문서당 중앙 4,119자, 최대 24,442자)
- 특약·약관·약정서는 검색으로 답하고, 평가에서 필요가 보이면 추가
