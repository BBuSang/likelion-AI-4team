# 9-3 상품명 찾기 — 가짜 상품 오탐 개선

## 왜
- 9-2 잠금 세트 3에서 가짜 상품 30개 중 17개에 실제 상품을 붙임 (기준 1 이하 미달)
- 남은 유형: **실제 상품의 고유한 이름 전체 + 지어낸 말** ('청춘 청년처음적금플랜') → LLM 확인이 "같은 상품을 다르게 부른 것"으로 봄
- 17개 중 16개는 1단계 결과를 그대로 인정한 경우라 답변에 '(추정)' 표시도 없음

## 개선 방향 (줄임말별 규칙 없이 일반 원칙 두 가지)
1. LLM 확인 지시에 원칙 추가: 질문 속 호칭의 **고유한 말은 모두** 후보 이름 안의 말(또는 그 줄임말·다른 표기: 영어↔한글, 기관 줄임말)과 대응해야 함. 이름에 대응하지 않는 고유한 말이 붙어 있으면 다른 상품일 수 있으니 고르지 않음
2. LLM 확인을 거친 상품은 결과가 1단계와 같아도 답변에서 "질문하신 '○○'을 '△△'으로 보고 답합니다"라고 밝힘

## 확인 세트 4 (잠금) — `analysis/s24_alias_check4.py gen` → `data/eval/alias_check4.jsonl`
- OpenAI로 생성, 구현 전에 만들고 질문이 제대로 만들어졌는지만 읽음 (판정 결과는 안 봄)

### 왜 미달인가
- 남은 35개는 '온결 **서울 메이트 공무원대출**', '맑은별 **행복지킴이 통장**'처럼 **실제 상품 정식 이름이 통째로** 들어 있음 → 1단계가 정식 이름 정확 일치로 보고 **바로 확정** (9-2의 애매함 신호 ①②에 걸리지 않음) → LLM 확인까지 가지 않아 새 원칙이 쓰일 기회가 없음
- 새 원칙이 실제로 적용된 유형(별칭 단어를 품은 가짜)은 4 → 0
- 이 35개는 답변에도 '(추정)' 표시가 붙지 않음 (exact)
- 줄임말 틀림 3개('마이카대출' → MY CAR 여러 상품, '이지원 보증대출' → 법인용이 아닌 쪽, '디딤돌대출' → 디딤돌 여러 상품)는 같은 이름 계열 상품이 여럿인 경우
